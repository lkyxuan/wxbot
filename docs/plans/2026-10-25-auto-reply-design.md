# 群聊「AI 自己判断接不接话」设计

状态：待确认（2026-10-25）

## 目标

某些群不再只在被 @ 时回复，而是每句话都交给 AI，由 AI 决定接不接。这是通用功能，
哪个群开、什么话题该接、多久最多主动说一次，都按群 / 智能体配置。美食群是第一个用户。

## 整体流程

```
群消息 ──> 机器人（这个群开了「AI 判断接话」：不看 @，每条都发）
              │  请求头带上：群名、发言人、是否 @ 了机器人
              ▼
          网关（该群的智能体配置了 auto_reply）
              ├─ 被 @ ─────────────────────────────> 完整智能体回答
              └─ 没被 @：第一步「判断」
                    便宜模型 + 最近几条聊天，输出 JSON：
                    {"reply": 要不要接, "labels": {"review": true, ...}}
                    ├─ reply=true 且不在冷却期 ──> 完整智能体回答，记下主动发言时间
                    ├─ 命中某个标签（如「在评价店」）──> 完整智能体「静默模式」：可以调工具记录，回复丢弃
                    └─ 都不是 ──> 返回 <NO_REPLY>
              ▼
机器人收到 <NO_REPLY> 或空回复：什么都不发（不发兜底话）
```

## 机器人改动（尽量少，方便合并上游）

1. **按群开关**：群聊设置每一行加一个勾选框「AI 判断接话」，存为 `group_ai_decide`（群名列表）。
   勾了的群：忽略全局「仅@时回复」，文字、图片、分享卡片都交给 AI；其它群行为完全不变。
2. **告诉网关有没有 @**：现有 `X-WX-*` 请求头里加一个 `X-WX-Mentioned: 1/0`。
   勾了「AI 判断接话」的群自动带上这些请求头（不依赖全局「附带会话信息」开关）。
3. **不回复标记**：AI 回复是 `<NO_REPLY>` 时，任何群和私聊都不发送。
   勾了「AI 判断接话」的群，空回复也不发、不用兜底话（其它群保持原来的兜底行为）。
   接口真正报错时：被 @ 的消息仍按原来的「接口失败固定回复」处理；没被 @ 的消息不发兜底话，
   只记日志（否则网关一挂，群里每句话都会刷一条报错）。

## 网关改动

智能体配置里加一个可选的 `auto_reply` 块，没配的智能体行为不变：

```json
"food": {
  "prompt_file": "agents/food.md",
  "mcp": ["food"],
  "auto_reply": {
    "judge_llm": {"model": "deepseek-chat"},
    "context_messages": 8,
    "reply_when": "有人问吃什么、去哪吃、某家店怎么样、求推荐餐厅",
    "labels": {
      "review": "这句话在评价某家具体的店（好吃、难吃、推荐、踩雷），或分享了店铺卡片"
    },
    "silent_on_labels": ["review"],
    "cooldown_seconds": 600
  }
}
```

- `judge_llm`：第一步用的模型，不写就用全局 `llm`。只带最近 `context_messages` 条聊天，不带工具、不带智能体长提示词，所以便宜、快。
- `reply_when`：什么情况该接话，用大白话写。网关拼成判断提示词，固定要求只输出 JSON。
- `labels`：顺便打的标签，给智能体用。美食群用它判断「是不是在评价店」，实时记口碑。
- `silent_on_labels`：命中这些标签且不接话时，让完整智能体以静默模式跑一遍（可以调工具记录，回复丢弃）。
  写成 `["*"]` 表示所有不接话的消息都旁听（费用更高，建议用标签筛）。
  静默调用时系统提示里写明：这次是旁听、命中了哪些标签、收到时间；群名、发言人照旧走 `X-WX-Chat` / `X-WX-Sender`。
  完整智能体收到的系统提示里会说明这次命中了哪些标签、是否需要回复。
- `cooldown_seconds`：没被 @ 时，同一个群在这段时间内最多主动说一次。被 @ 不受限制。
  冷却按群名（`X-WX-Chat`）计，拿不到群名时按智能体计。只在内存里记，重启网关清零。
- 判断结果出错（模型挂了、JSON 解析失败）时按「不接话」处理，只记日志。
- 完整智能体的提示词里补一句：没什么可说的就只回 `<NO_REPLY>`。

日志里每条都记判断结果（接 / 不接 / 标签 / 冷却中），方便部署后看判断准不准、实测费用。

## 规则默认值（美食群）

| 情况 | 动作 |
|---|---|
| 有人 @ 机器人 | 一定接 |
| 问吃什么、去哪吃、某家店怎么样 | 接（受 10 分钟冷却限制） |
| 评价某家店、分享店铺卡片 | 默默记下，不接 |
| 其它闲聊 | 不接 |

## 不在这次范围

- 美食助手怎么记口碑、周报怎么发：在「设计美食群 AI 助手」那边做，这里只提供 `labels` + 静默模式这个接口。
- 机器人侧的判断逻辑：全放在网关，机器人只负责「每条都发、收到不回复就不发」。

## 测试

- 网关：用假的大模型客户端写单元测试，覆盖被 @、判断接 / 不接、标签静默、冷却、判断出错、没配 auto_reply 的智能体。
- 机器人：测 `<NO_REPLY>` / 空回复不发送、`group_ai_decide` 群绕过「仅@时回复」、`X-WX-Mentioned` 请求头。
